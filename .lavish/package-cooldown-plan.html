The mechanism — planned edits

The two ecosystems get different tools because only one has native support. uv enforces the cutoff at every resolution with a relative duration — no dates, no relock machinery; a plain uv lock is always ≥14 days behind whenever it runs. Cargo has no equivalent (re-verified against cargo 1.93.1), so the Rust side is a pinned version plus an audit script that fails loudly when any locked crate is younger than 14 days. Reproducibility note: the rolling window moves, but uv.lock pins exact versions — day-to-day builds are byte-identical; only an explicit re-lock resolves anew.

Prerequisite — upgrade uv (0.5.14 → 0.12.x)

The installed uv (Jan 2025) only accepts RFC 3339 timestamps for exclude-newer; duration support ("14 days") and exclude-newer-package came later. uv self update (or brew) first — and note the irony is handled: uv is a standalone binary tool, not a package inside either lockfile, so upgrading it doesn't violate the cooldown being installed.

pyproject.toml — native rolling cutoff for every uv resolution

One line, no dates. Per-package escalation for a critical fix uses exclude-newer-package = { somepkg = "0 days" } with the justification in the commit — better than the allowlist I originally sketched.

Cargo.toml — pin pyo3 to the newest compliant version

The exact pin drags the whole same-versioned family (pyo3-ffi, -macros, -build-config, -macros-backend) down to 0.29.0 with it. Same minor version, so the cast/Bound API we compile against is unchanged — the rebuild gate verifies that claim.

Makefile — relock + audit targets (folds into the pending refine-benchmarks-and-tooling Makefile)

scripts/check-package-ages.py is the audit I ran to produce this page, formalized: it parses Cargo.lock and uv.lock, queries crates.io/PyPI for each resolved version's release date, and exits non-zero naming every violator. It needs network, which is why it's a separate target (and a CI job) rather than part of every local make check — see decision 2 below.

Apply sequence

  1. Upgrade uv (0.5.14 → 0.12.x) so exclude-newer = "14 days" parses
  2. Edit pyproject.toml and Cargo.toml as diffed above
  3. cargo update -p pyo3 --precise 0.29.0 (family follows automatically)
  4. uv lock (now rolling-compliant by construction) then uv sync
  5. Rebuild the release wheel, run all 63 tests, re-run the benchmark gates — the pyo3 downgrade touches every FFI call, so G2/G3 numbers get re-verified, not assumed
  6. Add the audit script + Makefile targets; run make audit clean
  7. Update the refine-benchmarks-and-tooling change (proposal + delta specs + tasks) so the cooldown is spec'd, not folklore; commit

Tradeoffs and risks — the honest column

CostConcretelyMitigation
Security fixes are delayed too A CVE patch released tomorrow waits 14 days like everything else. This is the classic cooldown tradeoff: you trade zero-day fix speed for zero-day compromise immunity. Documented override: Python uses uv's native exclude-newer-package = { pkg = "0 days" }; Rust pins the newer version explicitly. Justification goes in the commit message either way, and the audit script honors both.
pyo3 loses two patch releases 0.29.1 (Aug 2) and 0.29.2 (Aug 5) contain unknown fixes we forgo until Aug 16 / Aug 19. Compile + full test suite + benchmark gates re-run on 0.29.0 before committing. If something we need was fixed in .1/.2, the gates will say so and that becomes an override candidate.
Rust enforcement is soft Cargo can't refuse young versions at resolve time; a bare cargo update can walk past the pin for other crates. Cargo.lock is committed, and make audit fails on any young locked version — enforcement moves to CI/pre-release rather than resolve time.
ruff drops a minor (0.16 → 0.15.22) Lint rule set shifts slightly; a rule we currently pass could differ. make lint runs in the apply sequence; deltas fixed on the spot.
Audit needs network Release dates come from crates.io/PyPI APIs; offline make check would fail. Separate make audit target (decision 2) so day-to-day checks stay offline.

Decision record — all three settled

  • 1 Cutoff style: rolling, via uv's native setting. Your call, and the docs back it: exclude-newer = "14 days" in [tool.uv] — no hardcoded dates anywhere, no Makefile date plumbing. Reproducibility is preserved by the committed lockfile; only explicit re-locks re-resolve.
  • 2 Audit placement: separate make audit, run in CI and before releases, so make check stays offline-capable.
  • 3 Landing: fold into the open refine-benchmarks-and-tooling change and apply. Proposal, delta specs, and tasks get the cooldown added so it's spec'd, not folklore.
